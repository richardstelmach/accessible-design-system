# OwlA11y React API contract

Status: partially implemented beta contract, 21 October 2026. Product decisions accepted by Richard: React 18.3 and 19, styled components with token customisation, light theme for launch. Button, IconButton, Link, TextInput, Textarea, Select, Fieldset, Checkbox, Radio, ErrorSummary, DateInput, Dialog, Tabs, Alert, Badge, Stepper, Accordion, Card, Breadcrumb, Pagination and the Toast host are implemented. Modal backdrop is provided through Dialog CSS; all current families now have implementations. See packages/react/README.md for commands and verification limits.

## Shared conventions

Use named exports from @owla11y/react and import @owla11y/react/styles.css once. Package scope availability remains to be verified. Support JavaScript and TypeScript consumers. Preserve native element props and refs except explicit prohibited combinations. No generic polymorphic as/asChild API in the first release. React 18-compatible forwardRef is the implementation convention for public refs.

Generate stable IDs with React useId unless the consumer supplies id. A supplied id must be globally unique. Never derive DOM IDs directly from an unscoped item key. aria-describedby merges consumer IDs with generated helper/error IDs, removes duplicates and omits absent nodes. Components own structural roles/states; consumers must not override these with contradictory ARIA.

Single controls own visible labels, helper text and error association. error is absent or {message: string, id?: string}; message must be non-empty. errorDescribedBy references an externally rendered shared error and applies aria-invalid on the affected control without rendering another copy. Fieldset children-mode requires an explicitly identified shared error ID and affected controls; group-mode never forwards that error to each child. This integration must be demonstrated in a complete DateInput and ErrorSummary example.

For ordinary native controls use native value/defaultValue and onChange events (checked/defaultChecked for selections). Custom composites use onValueChange callbacks. Never supply both controlled and default props; never switch ownership after mount. Controlled state requires its change callback, except deliberately read-only native controls. Uncontrolled form controls must reset with their form. Controlled resets are the consumer's responsibility and must be documented.

Requirement defaults to required for TextInput, Textarea and Stepper; visible optional wording and native required are derived from one policy. Select follows the same required/optional adapter. Label requirements and group policies remain governed by the canonical form contracts. These defaults match the canonical requiredUnlessMarkedOptional policy.

Only native values determine hover, pressed, focus and disabled state. Do not expose a Figma State prop. Decorative icons are hidden from assistive technology. Do not accept raw HTML strings. Slots use ReactNode; plain-text labels/titles remain strings where required by contracts.

Invalid finite enums and conflicting prop modes are developer configuration errors with actionable development diagnostics. Do not silently coerce invalid keys, page numbers or numeric constraints. Type checking does not replace nonempty-string and dynamic-data validation. Decide production failure handling per component before implementation; document it alongside its tests.

## Integration rules and evidence

Dialog open is controlled to keep ownership explicit; the native open attribute is not a substitute for showModal. Reasons include close-button, escape, backdrop and action; transitions fire once per user intent, not in response to prop reconciliation. Dismissal and initial focus continue to follow dialog.yaml. Native dialog attributes such as closedby need feature detection and a tested fallback across supported browsers.

ToastProvider owns each mounted host lifetime. add returns the stable ID and takes a complete message; dismiss removes only that ID. Host labels include the Notifications region name and a localisable count formatter. Burst aggregation and modal deferral follow toast.yaml. Do not pass callbacks inside announced text or place a second live role on visible Toasts. The implemented host parts must each stay mounted once outside dialogs and route content, in the same document. Both priority channels defer during a native modal; immediate urgent feedback belongs in that modal with one announcement owner. The in-flow list remains mounted behind modal inertness. A 50ms announcement-delivery window batches same-turn events and commits an empty live-text state before repeated text; it never expires messages. regionLabel, emptyText, stateLabels, formatCountLabel(count) and formatAnnouncement(newEvents) support localisation; custom burst summaries must include the count and essential outcomes. Provider onDismiss(id) fires once per actual removal. No initial/history prop is provided: add only new events after the complete host mounts. See [Toast evidence](validation/react-toast-parity.md).

A Tabs item heading labels the fallback section as well as panel content; heading semantics must fit the page outline. Selection survives fallback changes; focus never disappears into newly hidden content. Explicitly test manual activation and Tab exit.

DateInput keeps raw strings and exposes required=true as a group policy rather than the single-field requirement presentation axis. name creates day/month/year submission names; partNames overrides all three with distinct explicit names. getDateInputIds(id) returns group/day/month/year IDs; supply the same id to DateInput so ErrorSummary never guesses its part IDs. The helper is pure and available without DOM access.

For Accordion, the new controlled adapter is additive: expandedIds/defaultExpandedIds replace initialExpandedIds only at the React layer. Do not change the independent-only canonical behaviour.

## Form-components checkpoint

Textarea, Select, Fieldset, Checkbox and Radio now follow the source contracts and use native elements. All five forward their native refs; className on a single field or choice styles its wrapper, while Fieldset className styles the fieldset. Invalid configuration throws an actionable error in all builds, matching the first four components.

Textarea keeps rows=5 and wrap=soft as native defaults; CSS sets the canonical 160px initial height, 128px minimum and vertical resizing. Select requires a first direct, enabled, visible empty-value option. Real options have explicit nonempty string values and plain text labels; optgroups have labels. React owns selected state through string value/defaultValue. Native size is omitted or 1, and tabIndex is omitted or 0; readOnly and multiple are unsupported. The opened menu remains browser/OS controlled.

Fieldset supports legendStyle page/default/section/subsection/compact and headingLevel none/h1/h2/h3/h4/h5/h6. Plain legend is the default. The consuming composite supplies an explicit error.id in children mode and passes that ID only to affected enabled controls; Fieldset does not clone children or infer affected controls. Legend, helper, one error and consumer controls remain direct native siblings. Optional wording is authored as part of the legend; there is no native required attribute on Fieldset.

Checkbox is optional unless native required is supplied for that individual choice. Optional wording is authored within its label. Checkedness controls submission; indeterminate is a separate DOM property set on mount and when its prop changes. Native activation clears indeterminate, so an aggregate owner must update it when child selections change. It is exposed after hydration, not as an SSR attribute. Checkbox has individual errors only for independent validation. Radio has no individual error API; shared missing-answer errors stay on Fieldset. Neither repeats group error/helper IDs automatically. Both preserve native reset and browser keyboard behaviour; controlled choices require onChange.

Native disabled Fieldsets govern descendant focus/submission and :disabled styling. A private context suppresses unavailable error presentation in library descendants, including TextInput. Custom controls remain responsible for their own presentation.

See [form comparison and validation](validation/react-forms-parity.md) for source blobs, Figma repairs, automated results and the remaining manual release evidence.

## Date and error-summary checkpoint

DateInput and ErrorSummary are implemented with a complete failed-submit example at ?date-errors. DateInput's ref targets Day. className styles its native fieldset. Default labels are Day/Month/Year; labels permits localisation. required=false appends the localisable optionalLabel once to the legend and removes required from all children; supply a legend without that suffix. purpose=date-of-birth enables bday-day/month/year only for the user's own birth date. Otherwise omit those autofill tokens. An explicit native form owner is forwarded to all three parts.

DateInput values are complete objects of three raw strings. Controlled editable values require onValueChange(next,{part}); controlled readOnly may omit it. Uncontrolled defaults use native reset without a second React state owner. A controlled form resets application state itself. The component never parses, normalises, pads, clamps or advances focus. Group errors do not invalidate every part. Children errors require an error plus a nonempty invalidParts list and associate one generated or supplied error ID only with those parts. Whole-component disabled/readOnly suppress error presentation. Calendar and service rules remain at an explicit consumer boundary; the example validator demonstrates missing parts, numeric ranges, Gregorian leap years and a birth date in the past.

ErrorSummary defaults to the visible h2 title There is a problem. errors must be nonempty. Stable issue IDs identify errors; duplicate current issues collapse, conflicting reuse of one ID throws, and text excludes list markers. The component sorts items by target document order after commit, then focuses only for a new finite-number/nonempty-string focusRequestKey. Pass a new key for every failed submit, including an initial server-rendered failed submission. Omit the key for passive display. Corrective rerenders do not refocus. A title owner adds one Error: prefix while mounted, restores it on resolution/unmount and preserves an externally replaced navigation title.

Summary target IDs must resolve uniquely to visible, enabled native inputs, textareas, selects or buttons in the tab order. contextId optionally identifies a label, legend or fieldset (whose direct legend is scrolled). Without it, individual fields use their label and group Radio/Checkbox targets use the legend where appropriate. For a whole-date error use ids.day and contextId=ids.group; for a part-specific error use the affected part ID, which resolves its own label. Fragments remain real href values. Modified clicks retain native link behaviour. Active summary targets must remain available; invalid configuration throws after commit. No Fieldset is focused and inline descriptions remain unchanged. Root ref targets the native div with persistent tabIndex=-1. Only the tested focus-based announcement strategy is exposed; role/aria-live overrides are excluded.

See [date/error comparison](validation/react-date-errors-parity.md) for precise evidence and remaining manual acceptance. These APIs do not imply screen-reader certification or full Next.js RSC acceptance.

## Dialog checkpoint

Dialog is implemented; see [Dialog comparison and validation](validation/react-dialog-parity.md) for adapter decisions and remaining manual checks. open is controlled. Use onOpenChange to accept close requests; direct consumer actions may update open themselves. Native method=dialog submission requests action only if the form has not prevented submission. children supplies the canonical Content slot and actions accepts native Button compositions. Forced decisions require enabled resolving actions and omit the close control. HeadingLevel 2–6 (default 2) controls semantics, with responsive H3 visual typography. Without a visible title, supply accessibleLabel. The forwarded ref is the native dialog; never set its open attribute directly.

One native modal is allowed per document. Container autofocus has a tested compatibility focus fallback and no tabindex. One maintained tabbable boundary handler covers accessible open shadow roots. The adapter owns light dismissal through pointer down/up and uses closedby=closerequest to preserve controlled ownership; forced mode uses none. ReturnFocusRef supplies a logical fallback/destination; consuming flows retain responsibility for navigation, resolving action handlers and fallback focus when triggers disappear. CSS uses the shared semantic modal overlay through ::backdrop; there is no public ModalBackdrop export.

## Tabs checkpoint

Tabs is implemented; see [Tabs comparison and validation](validation/react-tabs-parity.md). Items require stable unique nonempty IDs, distinct plain labels, a heading string and body content. The React adapter renders the heading at headingLevel 2–6 (default 3) with responsive H3 styling. Prefer labelledBy for an existing visible heading, otherwise label. Its native root div ref and useId-prefixed links/panels are stable through hydration.

The server/observer-free baseline exposes ordinary OwlA11y Link anchors and every section, with no widget roles or hidden content. After measuring the entire natural row, enhancement adds one selected panel and one list entry point at/above 48rem when it fits. Automatic activation requires immediately displayable content; manual mode commits on Enter/Space/click. defaultSelectedId defaults to the first item and is initial-only. Controlled selectedId requires onSelectedChange(id) and excludes defaultSelectedId; ownership cannot switch. Requests do not force a declining owner. Unknown explicit keys throw in every build. Removing an uncontrolled remembered key chooses the first remaining section without moving focus; hosts manage focus when they remove content.

All panel content stays mounted. The visible enhanced panel is a tabindex=0 stop; hidden uses native hidden. Responsive fallback removes widget attributes/handlers, reuses the anchors and shows every section. Resize never moves focus: re-enhancement requests the focus-containing section before hiding anything. For a conflicting controlled owner, keep the all-sections fallback until it accepts or focus leaves the conflict. Print exposes all sections. IDs/URL history synchronization, lazy loading, nested/vertical/disabled tabs and cross-panel required validation are not provided.


Alert and Badge are implemented in the [feedback batch](validation/react-feedback-parity.md). Both accept id/className/style/lang/dir/data attributes and reject behavioural or ARIA overrides. Alert's complete stateLabels map localises fixed prefixes; Badge uses only its visible label. Choose either Alert announcement semantics or a pre-existing application live region with Alert announcement=none. Badge announcements always belong to the application. No guarantee of spoken delivery follows from DOM role updates alone; manual acceptance remains required.


Stepper and Accordion are implemented in the [quantity/disclosure batch](validation/react-controls-parity.md). Stepper requires a positive finite step and contextual increment/decrement labels. Its input ref targets the native number field; raw strings remain editable, native constraint validation is retained, and button requests identify their source. Initial nonempty values must be finite, in range and step-aligned; later invalid edits are preserved. Uncontrolled reset restores the original value; controlled reset belongs to the host. Native stepUp/stepDown handles decimal arithmetic. Buttons disable only at a valid matching boundary or through whole-control/fieldset disabling. If a focused activated button becomes unavailable, focus returns to the input after commit; that fallback suppresses the duplicate polite announcement. Direct typing and native Arrow changes do not publish live text. formatValueAnnouncement(raw,label) can localise button-change speech. Unsupported readOnly, onChange/onInput ownership, placeholder, custom numeric ARIA and nonzero tabIndex throw.

Accordion requires explicit headingLevel (2–6). titleStyle defaults to the matching heading, independently of semantics. All items expand independently, panel DOM remains mounted and native buttons retain normal Tab/Enter/Space behaviour. panelLandmark opts into named regions; it is false by default. defaultExpandedIds is initial-only and maps the canonical initialExpandedIds; controlled expandedIds requires onExpandedChange and may decline requests. SSR/no-JS has ordinary headings with all bodies visible. Successful enhancement protects focused baseline content in addition to the requested defaults. An external collapse moves focus to its trigger before hiding an active panel. Print shows all bodies without changing state. The consuming application must expand and wait for panel visibility before focusing an error/deep-link target, as demonstrated in the preview. No single-open, disabled-item, lazy-loading or animation API is exported.

Card, Breadcrumb and Pagination are implemented in the [final-family batch](validation/react-navigation-parity.md). Card's ordinary div ref never acquires link/button semantics. image requires src, explicit alt and positive intrinsic width/height; fit=cover/contain and position control presentation. imageBadge is one existing Badge and requires an image. titleHref requires title, wholeCardClickable requires a linked title, and compact titleStyle requires headingLevel 2–6. titleLinkAttributes preserves native target/rel/download/events without replacing owned text/href/semantics. Use data-owla11y-card-ignore for an integration region excluded from surface forwarding; actual controls, labels, widgets and exposed shadow paths are excluded automatically. Container width selects horizontal layout at the canonical 32rem inner threshold; fallback is vertical. Content/action slots own their internal typography/spacing.

Breadcrumb accepts unique keyed ancestors and optional plain currentPage. No ancestors means no landmark. Controlled expanded/onExpandedChange excludes defaultExpanded; uncontrolled preference defaults false. Runtime width measurement is independent of the expanded presentation. SSR/print show the complete wrapping path and omit an inactive toggle. Native scrolling and the same anchors retain hierarchy and focus, and a focused toggle remains until blur when overflow disappears. No middle-item hiding, truncation or custom arrow navigation is provided.

Pagination requires known safe integers, renders nothing for zero/one page (zero uses currentPage=1 sentinel), and rejects invalid data. pageHref creates real URLs for the bounded window, directions, endpoints and page entry. presentation=auto measures actual width; numbered explicitly wraps and compact provides summary/directions/endpoints. An active numbered link stays visible through resize until focus leaves. labels provides optional text and number/page/summary/help/error/no-op formatters. formatPageLabel must include the complete visible formatted number. ASCII digit entry is the initial parser; display formatting does not broaden it.

For pageJump=true, supply jumpForm={action,pageName,hiddenFields?}; each field name must be distinct. This explicit GET fallback preserves query state without attempting to reverse-engineer pageHref. The required native text input uses numeric inputMode, no placeholder, 20ch width and an explicit compact Go button. Failed enhanced submissions retain raw text, render an associated inline error and focus the field. Current-page submissions are polite no-ops without focus movement. Before enhancement, native required/pattern validation and GET submission apply; the server remains authoritative for validation. Do not nest the generated form in an outer form.

Optional linkAttributes(page) preserves native integration. Optional onNavigate(page,{href,source:'link'|'jump'}) intercepts eligible primary link activation or valid jump; modifiers, alternate targets and downloads keep native behaviour. The callback receives a request, not a committed current-page change. The host owns asynchronous loading/failure/stale responses, currentPage, URL/history, document title, results focus on deliberate success, and Back/Forward restoration. The library does not invent results or fetch data. The preview uses the same URL builder for links/jump and preserves filter/sort parameters.


CodeBlock is implemented with required plain-text `code` and visible `label`, optional `copyable` (true), partial `labels` localisation and successful-copy `onCopy(code)`. Its ref targets the wrapper div. It reuses IconButton, preserves exact clipboard text, provides persistent visible polite feedback and adds a named code tab stop only for measured overflow. SSR and print wrap content; SSR omits inactive copy controls. See [the canonical CodeBlock contract](../components/code-block/code-block.yaml) and the CodeBlock validation report. Source/Figma reconciliation and the exported token foundation are recorded in the CodeBlock validation report. Manual screen-reader acceptance and publication remain release gates.

## Side menu

`SideMenu` provides primary or section navigation with direct links, static groups (default) and `expandable: true` Accordion groups. Required items; optional navigation aria-label (omitted by default, distinct names for multiple navigation purposes); expandable groups also require explicit headingLevel=2..6. Static-only navigation may use none. Optional currentId and expandedIds/onExpandedChange or defaultExpandedIds. `ResponsiveSideMenu` adds required visible drawer title label (independent of nav aria-label), controlled open/onOpenChange, mobilePresentation=drawer|inline (drawer), toggleLabel, closeLabel, drawerTriggerContainer and returnFocusRef; inlineHeadingLevel=2..5 is required for the outer in-flow Accordion, with deeper group headings. Both forward the nav ref. The existing Accordion/Button/Link/Dialog composition and routing/focus boundaries are defined in [the revised contract](../components/side-menu/side-menu.yaml) and [the side-navigation pattern](../patterns/side-navigation.yaml). The application controls successful route closure and destination focus; no automatic click-to-close or URL matching is supplied. Both exports have passed local design/API review; Figma construction/audit and remaining device acceptance are tracked in the validation report.

SideMenu supplies no outer padding or sidebar divider. Hosts compose those boundaries. ResponsiveSideMenu can render its existing drawer Button in a mounted same-document `drawerTriggerContainer` (for primary header navigation); omit it for section-local controls. Inline Accordion headers always stay local. The component retains ownership of ARIA relationships and actual trigger focus restoration.

Side menu source is merged through PR 49. Figma page `27 - Components - Side menu` (`1570:296`) is audited and published to the library on 27 October 2026; see the component guidance and validation receipt for preserved asset keys and CURRENT status. npm package publication and remaining device acceptance remain separate.


SideMenu current destinations use `aria-current="page"`, strong dark text and a 4px logical leading rule. The rule consumes the unchanged selected background/hover/active tokens; row surfaces use existing neutral surface/interaction tokens. Hover requires a hover-capable fine pointer, while transient touch pressed feedback and independent focus remain. Static and Accordion child lists add one 16px `spacing.inset.md` leading indent; flat top-level links stay unindented. No public API or selected-token mappings change.


## Table — local candidate

`Table` requires a nonempty caption and native thead/tbody/tfoot/colgroup sections, including at least one tbody. captionVisibility is visible (default) or visually-hidden; scrollLabel(caption) localises a scroll description appended to the native table aria-describedby. HTMLTableElement ref and table metadata/aria-describedby are supported; role/tabIndex/name overrides and direct custom section components are unsupported. Authors own row/column scopes and native cell content. The wrapper adds no role, name or tabindex. The native table is the keyboard scroll target before measurement/no-JavaScript/no ResizeObserver; fitting measured tables lose that extra stop/scroll description, preserving author descriptions and retaining table focus until blur after resize. No group or region landmark. Existing tokens only. [Scope, API and accessibility](../components/table/table.md).
