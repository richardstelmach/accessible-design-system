# Table

Accepted local candidate, 29 October 2026. [Contract](table.yaml) · [Planning and scope](../../docs/plans/basic-table.md). GitHub [PR 54](https://github.com/richardstelmach/accessible-design-system/pull/54) and [unpublished Figma candidate](https://www.figma.com/design/dVFI0q1cXMtmjUAkdvSWkk?node-id=1618-6) are ready for final review; wider manual release acceptance remains open.

Use a Table when information has meaningful relationships across rows and columns: references, comparisons and factual records. Use a list or description list for simpler content. This is not a layout tool or an interactive data grid.

```tsx
import {Table, Link} from '@owla11y/react';
<Table caption="Component status">
  <thead><tr><th scope="col">Component</th><th scope="col">Guide</th></tr></thead>
  <tbody><tr><th scope="row">Button</th><td><Link href="/button">Read the guide</Link></td></tr></tbody>
</Table>
```

## Caption, structure and ownership

A nonempty string `caption` is required and rendered first as a native caption. It is visible by default; use `captionVisibility="visually-hidden"` only with equivalent visible context nearby. This remains a real caption and table name. Do not supply a second caption, aria-label or aria-labelledby. The requirement is a component contract decision, not a claim that every HTML table must have a caption to meet WCAG.

Supply native thead/tbody/tfoot/colgroup sections (arrays and fragments allowed), with at least one tbody and no more than one thead/tfoot. Provide native tr/th/td rows and cells. Authors own truthful column and row scopes; the component does not infer headers or traverse arbitrary cell components. Complex spans, multi-level headers and nested tables are outside this first contract. Empty results remain host-owned content in an accurately spanned ordinary data cell.

The ref targets the native HTMLTableElement. id/className/style/lang/dir/data attributes and aria-describedby apply to it; language/direction also apply to the private viewport. Root handlers, dangerous HTML and role/tabIndex/name overrides are unsupported. Use a wrapping ancestor to theme variables shared by the viewport and table. Native column geometry and ordinary cell alignment remain author-owned; the default imposes no fixed overall table width.

## Small containers and keyboard use

Table never creates a region landmark or an enclosing ARIA group, including during SSR or without measurement support. Page headings and the native caption provide content navigation; the application owns meaningful page-level landmarks. The private overflow wrapper has no role, accessible name or tabindex. Do not automatically wrap each table in a named section.

The same table remains at every width. Cells reserve 12ch of text space plus existing insets, capped to the container width. Text wraps and row height grows; summed column minimums trigger local horizontal scrolling before letter-stack collapse. This is container/content driven, not a device breakpoint. Modern container units keep long visible captions within the viewport; older browsers retain native caption behaviour.

When content overflows, the native table receives tabindex=0. Its caption remains its accessible name and native table/header semantics remain unchanged. A visually hidden scroll description, generated by scrollLabel(caption), joins author aria-describedby IDs without replacing them. The default wording is “{caption}, horizontally scrollable”. This is a description, not a new table name. Review verbosity with assistive technology.

Tab reaches this native table directly, with no enclosing group to enter. Native arrow keys scroll the containing viewport, and Tab proceeds to cell links/buttons and then exits normally. No keyboard interception, grid role or roving focus is added. The focus indicator surrounds the viewport with a native-table fallback for browsers without :has support.

SSR/no-JavaScript/no-ResizeObserver retains the native table tab stop and scroll description. With measurement, a fitting table loses both, retaining only author descriptions. A table focused while scrollable keeps its access until blur if resizing removes overflow; focus never moves. Programmatic focus of an already fitting table does not manufacture a scroll state. The conservative baseline may add one extra table stop when measurement cannot run.

Measurement covers viewport/table resize, text/attribute/child changes and font readiness. Print reveals content, resets explicit minimum widths and wraps cells within the print width. The table's two-dimensional exception does not exempt surrounding prose or individual cell text from reflow requirements.

## Appearance and component reuse

One neutral treatment uses existing surface/default, text/default, text/heading and strong body typography. Cell insets are spacing.inset.sm (12px) block and spacing.inset.md (16px) inline. The native caption uses spacing.stack.sm beneath it. Existing responsive body typography inherits base/md/lg. A thin border/default outer border with radius.lg corners and row/column separators supplements semantics and header weight; these decorative boundaries are not claimed to meet 3:1 contrast. Text contrast is about 7.00:1 for body and 10.86:1 for headers on the default white surface.

Focus on the native table gives the viewport the existing ring/separator treatment inset inside its scrolling boundary. Cell padding leaves clearance for existing controls' focus rings. Forced colours retain native text, system boundaries and Highlight focus. Static cells are not interactive targets; existing components inside them retain their own minimum target rules.

Reuse actual Link, Badge and appropriate Button/form controls in cells. No Table row hover, selected/current state, striping or density variants are provided. Sorting, filtering, selection, editing, sticky/pinned columns, resizing/reordering and virtualisation require separate requirements. Outside Pagination and filters can be composed by the application without becoming Table features.

The 12ch minimum is a local content-sizing rule, not a new colour/spacing token. No primitive, semantic or component token was added. A coloured table-header role remains a conditional proposal, not an assumed need. No Tokens Studio pull/export is required when token sources are unchanged.
